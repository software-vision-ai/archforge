# archforge-er

**Purpose.** The ER notation: a schema of entities with ordered attributes, and relationships with
a cardinality at each end, as a metamodel over the MOF core (`er.xmi`, generated by `cargo xtask
generate er`) with the rules and commands written here. A schema is a member of the project's Model
(the shared core); comments on ER elements are the core's.

**Layer.** 6, the notations' layer, above the MOF core (4) and the shared core (5); pure, builds for
the portable target. Storage comes with the generated tables (gm2.31); the canvas later (gm2.10).

**Binding rules.** Every edit is a registered command with documented parameters, refused centrally
when unknown or out of range and refused by the handler, naming the key, when an id is not an element
of the expected kind. Ids in parameters are the elements' UUIDs. The MOF core enforces types,
bounds, containment and the derived union `ownedElement`; the ER rules (`rules`) add: names plain, at
most 128 characters and unique ignoring case among a schema's entities and an entity's attributes;
a type at most 64 characters; a key is never nullable; a relationship's ends are entities of its
schema. Removing an entity takes its attributes, the relationships that reach it and the trace
links on any of them, in one step (`commands::remove_entity`).

**The metaclasses.** `Schema` (entity, relationship), `Entity` (attribute), `Attribute` (type,
primaryKey, nullable, unique), `Relationship` (name, from, to, fromEnd, toEnd) and the enumeration
`Cardinality` (zeroOrOne, exactlyOne, zeroOrMore, oneOrMore).

**Public API.**

| Item | Signature |
|---|---|
| `registry` | `pub fn registry() -> Result<Arc<Registry<Store, ErView>>, String>`: the edit area and the ER commands |
| `Session`, `ErView` | `Session<Store, ErView>`; the view holds the selection |
| `universe_with`, `slabs`, `store` | a universe of the shared core, ER and others; the slabs of core and ER; a store over both |
| `rules::{name_problem, entity_name_free, attribute_name_free, schema_of, problems}` | the rules, for commands and for a whole store |
| `commands::{remove_entity, cardinality_name, specs}` | the cascade, the cardinality names in parameters, the command table |
| the generated constants, structs, `Cardinality`, `TABLES`, `JUNCTIONS` | as every generated metamodel |

Commands: `er.schema.{add, rename, remove}`, `er.entity.{add, rename, remove}`, `er.attribute.{add,
rename, set-type, set-flags, move, remove}`, `er.relationship.{add, set-ends, rename, remove}`,
`er.remove`, `view.select`, and the queries `er.schema.{list, get}` and `er.entity.{list, get}`.
The diagram commands return with the diagram metamodel (gm2.29, gm2.10).

**Tests.** `tests/er.rs`: the registry and the metamodel; every command's round trip on the store;
refusals that name their key and change nothing; removing an entity with a core folder, comment and
link around it, and the mixed delete through the engine; the sweep with ids of every kind; seeded
random sequences with the rules checked after each step and undo back to the start.

**Known lacks.** Nothing persists an ER model until gm2.31. No foreign keys or indexes (gm2.12).
Attribute types are free text; a dialect-aware list is a later decision.

**Non-goals.** Diagrams, storage, the canvas, MCP tools, the class model.
