# archforge-shell-api

**Purpose.** The shell's interfaces: what a notation's screens implement, and what they may use
from the shell, so a notation's screens build on this crate and never on the shell crate
(`archforge-ui-egui`) itself (`forge-ux/adr/0002`, "Notations are plugins", and `0003`, "Two
registries"). It holds the automation-id registry, the design (`ux`), the canvas geometry and
state that name no shell (`canvas`), with the editing under way on it (`editing`) and the skills
open in its tabs (`skill_tab`), the narrow context through which a notation's screens and the
shared controls reach the shell (`cx`, with what it is built of: the right panels' state
(`panels`, `appearance`), the menu bar's hold (`menu_bar`) and what its requests name (`state`,
`explorer`)), the interface `NotationUi` with what a notation keeps (`notation_ui`), the refusals in
the user's words, which ask the notations they are handed (`panels`, `engine_said`), the shared
controls the shell's panels and a notation's screens draw through the narrow context (`panels`),
with the problems a selection shows (`problems`) and the key presses they take (`actions`), the
interface `DiagramKind` with the data types it hands across (`kinds`, with what one frame's
drawing reads, `canvas::Drawing`, and what the pointer asked for, `editing::Action`), how a search
or a filter matches what is typed (`search`) and the translations machinery (`i18n`), with which
each crate registers its own catalogues, and the screens registry's type (`screens`): the
notations' screens parts the app registers, with the lists the shell reads made from them. The app
registers ER's and UML's parts and gives them to every shell it makes, and a test of the app's
holds them in step with the model registry (`archforge_notations::NOTATIONS`): one part for each
notation there, of its metamodel and with its diagram kinds, and none besides. The shell keeps the
old lists, which name ER and UML, for its tests only.

**Layer.** 9, the shell interfaces' layer: above `archforge-notations` (8), below the notations'
screens (10) and the shell (11). Builds for the portable target; holds no process or network code
(the gate's `layers` step scans it as it scans the shell). It takes egui, serde, serde_json, the
parameters of a command a tree row dropped on another runs (`NotationUi::drop_on`) and of the
commands the shared controls run, `log`, where an
engine error said as an internal one is kept,
`archforge-engine` (3), whose `Revision` a line end being dragged carries (the model's revision
the drag began on), whose session the context holds (and `kinds::active_kind` reads) and whose errors and reasons the refusals say, `archforge-mof` (4), whose elements, ids and store the interfaces' data types name,
`archforge-core` (5), whose skills a row of the Models tree lists under its element,
`archforge-diagram` (6), whose rectangles and line-end marks the canvas geometry reads, whose
notations a press on the canvas carries and whose project view the context's session is over, craft-i18n, whose `Folder` folds what a search is typed
against, and `icu_properties`, which says where a letter ends so a search never matches inside one.

**Non-goals.** Installing fonts and the app icon, which stay in the shell, as do the icons only one
notation draws until its screens crate takes them; the catalogues, which each crate that brings
text keeps, embeds and registers (the shell's are in `crates/ui-egui/src/i18n/`, ER's and UML's in
its `er/` and `uml/` folders until their screens crates take them); anything that
touches the file system or the operating system, which the host does through `Services`.
